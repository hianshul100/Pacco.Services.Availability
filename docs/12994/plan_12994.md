# Ticket 12994 — Add a `GET /health` endpoint returning `200` and `{"status":"ok"}`

**Project:** Common Architecture
**Target repository:** `hianshul100_Pacco.Services.Availability` (Pacco.Services.Availability microservice)
**Base branch:** `feature/12994/aidlc`
**Plan branch:** `12994-plan`

---

## 1. Goal / Why

Add a single, unauthenticated `GET /health` endpoint to the Pacco Availability service that responds `200 OK` with the JSON body `{"status":"ok"}`. The purpose is a smoke-test of the ADO AIDLC pipeline end-to-end: the smallest possible real code change that is verifiable by an automated assertion, plus a genuinely useful probe surface for container/Kubernetes readiness checks that today does not exist under that name.

The change must stay under ~20 lines of production code and must not alter any existing behaviour: no new dependencies, no new projects, no changes to CQRS handlers, persistence, messaging, or the Convey pipeline registration order.

---

## 2. Current state (files inspected)

The service is a .NET Core 3.1 Convey-based microservice laid out in the standard Pacco four-project Clean Architecture shape (`Api` → `Infrastructure` → `Application` → `Core`), declared in `Pacco.Services.Availability.sln`.

**HTTP surface is declared in exactly one place** — `src/Pacco.Services.Availability.Api/Program.cs`. There are no MVC controllers anywhere in the repository. Endpoints are registered inside `Convey.WebApi.CQRS`'s `UseDispatcherEndpoints(...)` builder in `Program.CreateWebHostBuilder`:

```csharp
.Configure(app => app
    .UseInfrastructure()
    .UseDispatcherEndpoints(endpoints => endpoints
        .Get("", ctx => ctx.Response.WriteAsync(ctx.RequestServices.GetService<AppOptions>().Name))
        .Get<GetResources, IEnumerable<ResourceDto>>("resources")
        .Get<GetResource, ResourceDto>("resources/{resourceId}")
        .Post<AddResource>("resources",
            afterDispatch: (cmd, ctx) => ctx.Response.Created($"resources/{cmd.ResourceId}"))
        .Post<ReserveResource>("resources/{resourceId}/reservations/{dateTime}")
        .Delete<ReleaseResourceReservation>("resources/{resourceId}/reservations/{dateTime}")
        .Delete<DeleteResource>("resources/{resourceId}")))
```

Two registration styles already coexist there:
- the **CQRS generic style** (`.Get<TQuery, TResult>(...)`, `.Post<TCommand>(...)`), which routes through the query/command dispatchers; and
- the **raw delegate style** — the existing root endpoint `.Get("", ctx => ctx.Response.WriteAsync(...))`, which writes directly to the `HttpResponse` and resolves `AppOptions` from `ctx.RequestServices`.

The raw delegate style is the precedent this ticket follows: a health probe has no command, no query, and no handler, so forcing it through the CQRS dispatcher would require a new `Query` type, a new handler, a DTO, and DI registration — far more than 20 lines, for no behavioural gain.

**Pipeline / middleware.** `src/Pacco.Services.Availability.Infrastructure/Extensions.cs` → `UseInfrastructure(this IApplicationBuilder app)` composes the request pipeline in this order: `UseErrorHandler()` → `UseSwaggerDocs()` → `UseJaeger()` → `UseConvey()` → `UsePublicContracts<ContractAttribute>()` → `UseMetrics()` → `UseMiddleware<CustomMetricsMiddleware>()` → `UseCertificateAuthentication()` → `UseRabbitMq()` + `SubscribeCommand<...>` / `SubscribeEvent<...>`. Endpoint delegates registered in `UseDispatcherEndpoints` run *after* this pipeline, so the new endpoint inherits error handling, tracing and metrics without any extra wiring.

**Existing probe surfaces.** There is no `/health` route today. What exists instead:
- `consul.pingEndpoint: "ping"` in `src/Pacco.Services.Availability.Api/appsettings.json` — Consul health-checks the Convey-provided `ping` route registered by `UseConvey()`.
- `metrics.prometheusEnabled: true` — Prometheus scrape endpoint via `UseMetrics()`.
- The root route `GET /` returns the plain-text service name (`"Pacco Availability Service"` from `app.name`).
- `logger.excludePaths` and `jaeger.excludePaths` in `appsettings.json` are both `["/", "/ping", "/metrics"]` — i.e. the existing probe paths are deliberately excluded from log/trace noise.

**Authentication.** No endpoint in `Program.cs` passes an auth flag, and `security` in `appsettings.json` only sets `certificate.header`; `UseCertificateAuthentication()` is therefore inert for inbound requests in the local/tests/docker profiles. The new endpoint needs no auth opt-out.

**Tests.** `tests/` holds five xUnit projects (all listed in the `.sln`): `Tests.Unit`, `Tests.Integration`, `Tests.EndToEnd`, `Tests.Performance`, `Tests.Shared`. HTTP-level tests live in `tests/Pacco.Services.Availability.Tests.EndToEnd/Sync/` (`GetResourceTests.cs`, `AddResourceTests.cs`). They use xUnit + Shouldly, boot the real app through `PaccoApplicationFactory<Program>` (`tests/Pacco.Services.Availability.Tests.Shared/Factories/PaccoApplicationFactory.cs`, which forces `UseEnvironment("tests")` → `appsettings.tests.json`), set `factory.Server.AllowSynchronousIO = true`, and assert with `response.StatusCode.ShouldBe(HttpStatusCode.X)`. Test method names are snake_case behavioural sentences, and arrange code sits in a trailing `#region Arrange`.

**Docs / manual verification.** `Pacco.Services.Availability.rest` at the repo root is the REST Client request catalogue referenced by `README.md`; every HTTP route is listed there with `###` separators against `@url = http://localhost:5001`.

**CI.** `.travis.yml` runs `./scripts/build.sh`; `scripts/test.sh` is a bare `dotnet test`. No lint/format gate exists, so the only mechanical bar is that the solution builds and existing tests still pass.

## 3. Scope

**In scope**
- One new route `GET /health` on the Availability service returning HTTP `200` with body `{"status":"ok"}` and `Content-Type: application/json`.
- One new end-to-end test class asserting status code and body, following the existing `Tests.EndToEnd/Sync` conventions.
- Adding the request to `Pacco.Services.Availability.rest` so the route is discoverable the same way every other route is.

**Out of scope**
- Any dependency-aware health reporting (Mongo/RabbitMQ/Redis/Consul reachability), `ASP.NET Core HealthChecks`, or `/health/live` + `/health/ready` split. Explicitly deferred: the acceptance criteria demand a static payload, and probing dependencies would change failure semantics.
- API Gateway exposure. `hianshul100_Pacco.APIGateway/src/Pacco.APIGateway/ntrada.yml` (module `availability`, lines ~75–127) would need a new `upstream: /health` route to publish this externally; the ticket is scoped to a single service, so the gateway is left untouched.
- Rolling the endpoint out to the other twelve Pacco service repositories.
- Authentication/authorisation, UI, persistence, new events, and any change to existing routes.
- Adding `"/health"` to `logger.excludePaths` / `jaeger.excludePaths` in the four `appsettings*.json` files. Desirable for probe noise later, but it edits existing configured behaviour in four files and is not required by any acceptance criterion.

## 4. Design / approach

**Decision 1 — register the route as a raw delegate inside the existing `UseDispatcherEndpoints` block in `Program.cs`, immediately after the root `.Get("")` registration.**
Trade-off: keeps the diff to ~5 production lines and mirrors the root-endpoint precedent, at the cost of the handler living in `Program.cs` rather than a dedicated class — acceptable because it is a constant-payload probe with zero business logic, and the layering rule ("no business logic in HTTP handlers") is trivially satisfied since there is none.

**Decision 2 — write the JSON literal explicitly rather than serialising an anonymous object or DTO.**
The handler sets `ctx.Response.StatusCode = 200`, `ctx.Response.ContentType = "application/json"`, then `await ctx.Response.WriteAsync(HealthResponseBody)` where `HealthResponseBody` is a `private const string` on `Program` holding `{"status":"ok"}`. Trade-off: bypasses Convey's configured JSON serializer, which is exactly the point — the payload contract in AC2 is byte-exact and must not drift if serializer casing/naming settings change. It also avoids introducing a DTO type into `Application` for a non-CQRS concern. Using a named constant satisfies the "no magic strings" standard.

**Decision 3 — route literal `"health"`, not `"/health"` and not `"api/v1/health"`.**
`UseDispatcherEndpoints` registers paths without a leading slash (`""`, `"resources"`, `"resources/{resourceId}"`), so `"health"` is what resolves to `GET /health`. The path constant `HealthEndpointPath = "health"` sits beside the body constant. Trade-off: this skips the `/api/v1/...` versioning convention from the global standards — deliberately, because AC1 fixes the path at `/health`, operational probe endpoints are conventionally unversioned, and the service has no `/api` prefix anywhere.

**Decision 4 — no new project, package reference, or DI registration.**
`Microsoft.AspNetCore.Http` (for `HttpResponse.WriteAsync`) and `Convey.WebApi.CQRS` are already `using`-imported in `Program.cs`; nothing needs to be added to `Pacco.Services.Availability.Api.csproj`.

**Decision 5 — verify at the E2E layer only, no unit test.**
The behaviour is entirely "the route is wired and returns the right bytes", which only a hosted-pipeline test can prove; a unit test of a constant string asserts nothing. The new test therefore lands in `Tests.EndToEnd`, which already owns HTTP-contract assertions. Trade-off: `Tests.EndToEnd` boots the full app (`UseRabbitMq()`, Mongo), so the test inherits the suite's existing infrastructure requirement — consistent with `GetResourceTests`/`AddResourceTests`, and no *new* infrastructure dependency is introduced.

**Decision 6 — do not touch `CustomMetricsMiddleware`.**
`src/Pacco.Services.Availability.Infrastructure/Metrics/CustomMetricsMiddleware.cs` keys its `_metrics` dictionary on `GET:/resources` and `POST:/resources` only; an unmatched path short-circuits to `next(context)`. `/health` therefore passes through untouched with no counter and no code change.

## 5. Data flow

The flow is a single pass through the already-composed pipeline; no dispatcher, no repository, no broker.

```mermaid
sequenceDiagram
    participant Client as Probe / smoke test
    participant Kestrel
    participant Pipe as UseInfrastructure pipeline
    participant Ep as UseDispatcherEndpoints
    participant H as health delegate (Program.cs)

    Client->>Kestrel: GET /health
    Kestrel->>Pipe: request
    Note over Pipe: UseErrorHandler → UseSwaggerDocs → UseJaeger →<br/>UseConvey → UsePublicContracts → UseMetrics →<br/>CustomMetricsMiddleware (no key match, passthrough) →<br/>UseCertificateAuthentication (inert)
    Pipe->>Ep: routing
    Ep->>H: match "health"
    H->>H: StatusCode = 200; ContentType = application/json
    H-->>Client: 200 {"status":"ok"}
```

No call reaches `ResourcesMongoRepository`, `MessageBroker`, `CustomersServiceClient`, or any `ICommandHandler`/`IQueryHandler`, so the endpoint stays available even when Mongo/RabbitMQ are degraded — which is the correct semantic for a static liveness probe.

## 8. Build sequence

1. **Add the two constants to `Program`** in `src/Pacco.Services.Availability.Api/Program.cs` (`HealthEndpointPath`, `HealthResponseBody`). Compiles standalone; no behaviour change yet.
2. **Register the route** — insert the `.Get(HealthEndpointPath, ...)` delegate into the `UseDispatcherEndpoints` chain immediately after `.Get("", ...)`. Order inside the chain is not semantically significant (paths are distinct), but placing it next to the other raw-delegate route keeps the CQRS registrations contiguous. Build with `dotnet build Pacco.Services.Availability.sln`.
3. **Smoke it manually** — `./scripts/start.sh` (or `dotnet run` in `src/Pacco.Services.Availability.Api`) then `curl -i http://localhost:5001/health`; expect `HTTP/1.1 200`, `Content-Type: application/json`, body `{"status":"ok"}`. Confirm `GET /` still returns `Pacco Availability Service` and `GET /resources` still responds — proof of "no existing behaviour modified".
4. **Add the E2E test** `tests/Pacco.Services.Availability.Tests.EndToEnd/Sync/GetHealthTests.cs`. It depends on step 2 being in place to pass, and on nothing new: `PaccoApplicationFactory`, xUnit, Shouldly, and `Newtonsoft.Json` are already referenced by `Pacco.Services.Availability.Tests.EndToEnd.csproj`.
5. **Run the suite** — `./scripts/test.sh` (`dotnet test`) with the Pacco infrastructure containers up (`hianshul100_Pacco/compose/mongo-rabbit-redis.yml`), the same prerequisite the existing `Sync` tests already have. Assert no regression in `GetResourceTests` / `AddResourceTests`.
6. **Append the `###` block to `Pacco.Services.Availability.rest`** — documentation only, deliberately last so it never blocks the build.
7. **Commit** as `feat(api): add GET /health endpoint returning status ok` (Conventional Commits, scope `api` = the project actually changed).

## 9. Risks & rollback

| Risk | Likelihood | Mitigation |
|---|---|---|
| Route literal written as `"/health"` instead of `"health"`, producing `GET //health` or a 404. | Medium — easy slip | Every existing registration in `Program.cs` omits the leading slash; step 3's `curl` and the step-4 test both catch it before merge. |
| Response body drifts from the exact contract (e.g. `{"Status":"ok"}` or pretty-printed) because a future refactor swaps the constant for object serialisation. | Low | Decision 2 pins a `const string`; the E2E test asserts on the deserialised `status` value **and** on the presence of `"status":"ok"`, so a casing change fails the build. |
| `UseCertificateAuthentication()` or a future auth middleware starts rejecting the probe. | Low | `security.certificate` in `appsettings.json` only defines `header` and the middleware is inert; step 3 verifies anonymous access explicitly against the `local` profile, and the E2E test verifies it against the `tests` profile. |
| Probe traffic floods Seq/Jaeger because `/health` is absent from `logger.excludePaths` / `jaeger.excludePaths`. | Medium once probes are wired up | Accepted for this ticket (out of scope, §3). Follow-up: add `"/health"` to those two arrays in all four runtime `appsettings*.json` files. |
| `Tests.EndToEnd` fails in an environment without Mongo/RabbitMQ, and the new test is blamed. | Medium | Pre-existing condition of the whole `Sync` suite, not introduced here; note it in the PR description. If the smoke pipeline must run without infrastructure, run `dotnet test tests/Pacco.Services.Availability.Tests.Unit` separately and verify `/health` with the step-3 `curl` against a running container. |
| Consul/Fabio behaviour changes. | None | `consul.pingEndpoint` stays `"ping"`; the new route is additive and unregistered with Consul. |

**Rollback:** the change is two files of purely additive code plus one doc line. `git revert <sha>` restores the previous `Program.cs` and removes the test class with no data, schema, contract, or message-broker migration to unwind. No feature flag is warranted for a stateless additive route.
